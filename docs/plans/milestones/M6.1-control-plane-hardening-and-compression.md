# Constructicon M6.1 — control-plane hardening and architectural compression

**Status:** implementation-ready review plan  
**Base:** `main` at `3cff327d0e09b243b29d5aa2b517014f5223a7d2`  
**Nature:** corrective follow-up to M6 rev 2; no new milestone architecture

## Context

M6 established the correct public concepts:

```text
Actor       who is asking
Command     one durable mutation intent
Run         long-lived work
Reference   bounded access to immutable detail
```

The central design remains approved:

```text
MCP ─┐
     ├─→ ControlPlane → Constructicon domain operations
CLI ─┘
```

The implementation is substantial and fundamentally sound, but the final merged
state contains several places where one authoritative idea has two paths with
slightly different semantics. M6.1 removes those parallel truths.

This is not a rewrite. It is a compression pass governed by four laws:

1. **Authority before lookup.** Every addressed record is authorized before any
   payload is returned, regardless of whether it is reached through a status tool,
   a detail tool, or an MCP resource.
2. **Plan before mutation.** Every public mutation enters one command session,
   stores one typed immutable plan, applies or reconciles once, and stores one
   terminal response.
3. **Snapshot before pagination.** Every multi-page query binds one reproducible
   store revision, not merely the current list length.
4. **Terminality before immutable reference.** A `DetailRef` is issued only for a
   value that can no longer change under that identity.

## Current defects this plan closes

### Release integrity

- The merged `main` verification run is red because
  `tests/api/test_counterfactual.py` imports test fixtures that do not exist.
- Temporary M6 integration assets remain committed:
  `.m6-docs/part000`, `apply-m6-docs.yml`, `finalize-m6-docs.yml`, and the source
  artifact upload step in `verify.yml`.
- `docs/ARCHITECTURE.md` still describes M6 as pending and omits the final
  control-plane section.
- `main` has no required-status branch protection, so a red exact head was merged.

### Authority and boundedness

- `commands_status()` enforces command owner-or-admin visibility, but
  `details_read(constructicon://commands/...)` bypasses the same rule.
- `commands_status()` returns the complete `CommandRecord`, including potentially
  large request, plan, manifest, inputs, and response documents. It violates the
  bounded-response contract that detail references were meant to enforce.
- Several `DetailRef`s name mutable values: a run result before terminality and a
  prepared command before completion. The API calls them immutable even though the
  bytes can change.

### Command-law drift

- The SQLite `ControlStore` correctly returns `in_progress` for any unexpired
  command owner, but `InMemoryControlStore` lets another task using the same
  `owner_id` reclaim the command at a higher epoch. The test double therefore does
  not exercise the same contract.
- The three response-loss seams are tested for start, approval, promotion, and
  rollback, but not cancel, resume, reproduce, or counterfactual.
- Terminal rejections do not pass through the same after-completion fault probe as
  successful command responses.
- `ControlPlane` reconstructs plans from generic dictionaries using manual
  `_object`, `_string`, and digest helpers instead of validating a small set of
  typed private plan models.

### Public escape paths and lifecycle

- `Constructicon.start/resume/reproduce/cancel/promote/rollback` remain public
  mutation paths that bypass authenticated actors and the command ledger.
- `ControlPlane` exposes its store, system, cursor codec, detail resolver, run host,
  and mutable fault probe directly.
- MCP lifespan reaches into `control.run_host` instead of delegating lifecycle to
  `ControlPlane`.
- `RunHost` catches and swallows arbitrary `BaseException`, which can launder a
  hard-death signal into a silent `None` result.
- Startup recovery queries only the first 100 recoverable runs once; later rows can
  remain stranded indefinitely.
- `RunHost.wait()` is race-prone because completed tasks are removed before a late
  waiter necessarily observes them.

### Snapshot and structural debt

- Candidate-version pagination recomputes “candidate” against the current stable
  pointer on every page. A promotion between pages can shift the list.
- Reverse-dependency pagination recomputes against the latest registry world and
  binds only the list length, not the registry revision.
- The cursor checksum is unkeyed. It is useful for accidental corruption but must
  not be described as proof or authority.
- `Constructicon` reaches into private walker methods to load manifests and
  materialize results.
- Permanent SQLite modules are named after implementation history
  (`sqlite_legacy`, `_sqlite_v5_*`) rather than their enduring responsibilities.
- Dead public control codes remain without producers.

> credential-free `uv run verify` gate. No temporary integration workflow or
> payload remains in the repository. Every public mutation enters `ControlPlane`
> and one fenced command session. The same command has one live owner even when two
> calls originate in the same process, and every one of the eight mutations is


## A2. Make command reads bounded and consistently authorized

Replace `CommandView(record=CommandRecord, detail=...)` with a bounded
`CommandSummary`:

```python
class CommandSummary(BaseModel):
    command_id: str
    operation: str
    state: Literal["prepared", "committed", "rejected"]
    actor_id: str
    request_hash: Digest
    created_at: AwareDatetime
    updated_at: AwareDatetime
    completed_at: AwareDatetime | None
    detail: DetailRef | None
```

Rules:

- `commands_status()` returns only `CommandSummary`.
- A nonterminal command has `detail=None` because its full record is mutable.
- A terminal command receives one immutable detail reference.
- The full `CommandRecord` remains the durable store model and is available only
  through chunked detail resolution.
- The command visibility predicate is defined once:

```text
command actor OR constructicon:admin
```

Both `commands_status` and `DetailResolver` call the same predicate.

Add tests:

- Alice creates a command; Bob with `constructicon:read` cannot read it through
  either `commands_status`, `details_read`, or the MCP command resource.
- An administrator can read it through all three paths.
- A large request/plan never appears inline in `commands_status`.
- The serialized summary stays below a pinned response-byte budget.

## A3. Make detail references genuinely immutable

Keep the public noun `DetailRef`, but make its invariant strict:

```python
class DetailRef(BaseModel):
    uri: str
    media_type: str = "application/json"
    digest: Digest  # required
```

`details_read` accepts the typed `DetailRef`, not an unverified bare URI, and
checks that the current canonical value still matches its digest.

Reference policy:

| Family | When a ref may be emitted |
| --- | --- |
| Manifest | always; identified by stored manifest hash |
| Journal event | always; `(run_id, seq)` is write-once |
| Component version | always; exact content hash |
| Attestation | always; journal-minted write-once record |
| Approval | always; write-once record |
| Command | only after `committed` or `rejected` |
| Run result | only after a terminal run state |

Consequences:

- Remove `RunSubmission.status_ref`; the client already has `run_id` and calls
  `runs_status`.
- `RunSummary.result_ref` becomes optional and appears only when terminal.
- `RunResultPreview.detail` is optional until terminal.
- `CommandSummary.detail` is optional until terminal.
- MCP resources for command and result detail return a typed rejection while the
  value is still live.
- All reference creation and parsing moves into one `DetailAddress`/builder module;
  `ControlPlane` no longer manually concatenates URI strings.

Bump the control response schema version because the wire contract changes.

Add tests:

- every emitted ref reconstructs bytes whose digest matches the ref;
- a forged or stale digest is refused;
- no nonterminal run/command emits an immutable ref;
- chunk continuation reconstructs the same canonical bytes;
- authorization occurs before serialization.

## A4. Repair the `ControlStore` contract

Fix `InMemoryControlStore.claim_command()`:

```text
any unexpired prepared command → in_progress
```

The result must not depend on whether the incoming call uses the same process
`owner_id`; `owner_id` identifies a host, not one request coroutine.

Create one parametrized control-store contract suite and run it against:

```text
SqliteJournal
InMemoryControlStore
```

The shared suite covers:

- simultaneous same request/key, different owners → one claimed, one in progress;
- simultaneous same request/key, same owner → one claimed, one in progress;
- same key, different request → conflict;
- expired claim → epoch increments exactly once;
- plan is write-once and identical repetition is idempotent;
- contradictory plan → damage;
- terminal response is write-once and identical repetition is idempotent;
- approval is write-once and command-bound.

This turns the I6 test double into a real second consumer rather than an unused
look-alike.

## A5. Put every command outcome through one private session

Introduce one private, non-extensible `_CommandSession`. It is implementation
compression, not a public protocol or operation-plugin framework.

Responsibilities:

```text
authorize
→ normalize and claim
→ decode replay or conflict
→ load/store one typed plan
→ apply fault probes at all three seams
→ commit or reject one terminal response
```

Use four private frozen Pydantic plan shapes:

```text
_RunPlan          run_id + manifest + inputs + origin
_RunTargetPlan    run_id
_ApprovalPlan     ApprovalRecord
_PromotionPlan    component + baseline + target + attestation
```

Remove manual `_object`, `_string`, and `_optional_digest` plan parsing. The
SQLite command row remains generic JSON; the owning operation validates its plan
through one exact model.

A terminal rejection uses the same completion path and the same
`after_command_completion` probe as a successful terminal response.

Expand the response-loss matrix to all eight mutations:

```text
runs_start
runs_cancel
runs_resume
runs_reproduce
runs_counterfactual
runs_approve
registry_promote
registry_rollback
```

For each operation, inject:

```text
after_plan
after_domain_mutation
after_command_completion
```

Assert one command, one domain fact, and the same terminal response after retry.
Use a table-driven test harness rather than 24 copied tests.

## A6. Close the public mutation escape hatch

`ControlPlane` becomes the sole public run/approval/promotion mutation surface.

`Constructicon` remains the injection root and domain engine, but its control
mutators become private implementation verbs used by `ControlPlane`:

```text
_prepare_run
_request_cancel
_promote_version
_rollback_version
```

Remove or deprecate the public unauthenticated methods:

```text
start
resume
reproduce
cancel
promote
rollback
```

Keep explicit bootstrap operations:

```text
register
promote_initial
validate
describe
```

Python callers that need durable control construct a `ControlPlane` with a static
actor, exactly as stdio does. Do not add a second “local mutation” facade.

Update tests by layer:

- runtime tests may call the walker directly;
- domain assembly tests may use private/bootstrap verbs where the boundary itself
  is under test;
- API and e2e tests use `ControlPlane` for every public mutation.

Add a structural test that exported API documentation and MCP/CLI code contain no
call to a private domain mutator outside `ControlPlane`.

## A7. Make `ControlPlane` own its lifecycle and internals

Make implementation fields private:

```text
_system
_store
_cursors
_details
_run_host
_fault_probe
```

Expose only:

```python
async def startup(self) -> None
async def shutdown(self) -> None
```

MCP lifespan calls those two methods and never reaches into `run_host`.

Inject the fault probe in the constructor for tests; do not expose a mutable public
attribute in production.

## A8. Make `RunHost` truthful and complete

- Catch `Exception`, not `BaseException`.
- Let hard-death signals (`SystemExit`, `KeyboardInterrupt`, `InjectedCrash`, and
  other `BaseException`s) propagate to the task failure path.
- Report unexpected task exceptions through a required/default event-loop failure
  sink; never silently convert them into `None`.
- Remove `RunHost.wait()` from the production contract. Tests wait through durable
  `runs_status` polling; `RunHost` owns workers, not results.
- Replace one-shot `recover(limit=100)` with a bounded refill loop:
  - launch at most the configured queue/concurrency capacity;
  - when a hosted task finishes, query the next recoverable page;
  - eventually consider every PENDING or lost RUNNING run;
  - never create an unbounded pile of semaphore-waiting tasks.
- Shutdown still abandons without setting cancellation intent.

Tests:

- more than 100 recoverable runs are eventually considered;
- concurrency never exceeds the configured ceiling;
- a hard-death test signal is observable and the durable run remains reclaimable;
- shutdown does not set `cancel_requested` or `CANCELLED`;
- ownership fencing still chooses one host.

# PR B — M6.2 internal compression

PR B begins only after PR A and post-merge `main` are green.

## B1. Make registry pagination revision-correct

Add one immutable registry revision:

```python
class RegistryRevision(BaseModel):
    registration_seq: NonNegativeInt
    promotion_seq: NonNegativeInt
```

`RegistrySnapshot` records the revision that produced it. `RegistryStore` gains a
historical read at an exact retained revision; no new table is required because
component registrations and promotions are append-only and already sequenced.

All registry pages bind the first page's revision:

- versions page uses the registration upper sequence;
- candidates page also pins the stable version at that promotion revision;
- reverse dependencies are computed from the exact historical snapshot;
- comparison and impact data use one snapshot, never two current reads.

Cursor continuation carries the registry revision, not merely list length.

Tests:

- registering a version between pages does not enter the old sequence;
- promoting a new stable between candidate pages does not shift or duplicate rows;
- changing a composite between rdeps pages does not alter the old closure;
- a new query observes the new registry revision.

## B2. Calibrate cursor integrity honestly

Do not introduce key-management machinery merely to make cursors look like
security tokens. They are continuation data, and every read independently checks
actor authority.

- Rename `check` to `checksum`.
- Document it as accidental-corruption detection, not authentication or proof.
- Keep actor, endpoint, query, and revision validation.
- Validate every continuation bound against an actual store revision or maximum.
- Use exact schema literals.
- Remove “tamper-evident” language wherever it appears.

A future distributed/public deployment may add an injected HMAC signer with its
first real key-management consumer; M6.2 does not build one prematurely.

## B3. Remove private walker reach-through

Promote the runtime operations M6 genuinely needs into explicit internal methods:

```python
Walker.load_manifest(run_id)
Walker.materialize_run(run_id)
```

`Constructicon` delegates to those methods rather than calling `_load_manifest`
and `_materialize`.

Do not move materialization into the control layer; it is execution semantics and
belongs with the walker.

## B4. Split `ControlPlane` by responsibility without adding public concepts

Retain one public `ControlPlane` facade. Internally compose exactly two concrete
private collaborators:

```text
_ControlQueries    bounded reads, pages, details
_CommandExecutor   command sessions and domain mutations
```

No protocols, no plugin registry, and no generic operation dispatch table.
`ControlPlane` remains the only public name and delegates each method once.

Target outcomes:

- `api/control.py` becomes a small facade and lifecycle owner;
- command law exists only in `_control_commands.py`;
- paging and summaries exist only in `_control_queries.py`;
- detail authorization/addressing remains in `detail.py`.

## B5. Rename SQLite internals by enduring responsibility

Keep one concrete public `SqliteJournal`, but remove milestone-history names:

```text
sqlite_legacy.py          → _sqlite_execution.py / responsibility-based facets
_sqlite_v5_control.py     → _sqlite_control.py
_sqlite_v5_reads.py       → _sqlite_queries.py
_sqlite_v5_schema.py      → _sqlite_schema.py
```

Recommended permanent decomposition:

```text
_sqlite_base.py       connection, transaction, clock, fault probe
_sqlite_schema.py     schema creation and versioned migrations
_sqlite_execution.py  runs, events, checkpoints, effects, leases, attestations
_sqlite_registry.py   component versions and promotions
_sqlite_control.py    commands and approvals
_sqlite_queries.py    bounded read projections
sqlite.py             one concrete assembled class
```

Private mixins are acceptable implementation decomposition; version numbers and
“legacy” are not permanent concepts. Keep migrations explicitly version-named
inside `_sqlite_schema.py`.

Rename the migration test to `test_sqlite_v4_to_v5.py`.

## B6. Remove dead public contracts and duplicate naming

Remove or implement every public `ControlCode`. At the time of this review the
following have no producer and should be deleted rather than advertised:

```text
RUN_NOT_RESUMABLE
COUNTERFACTUAL_EFFECT_UNSUPPORTED
DETAIL_TOO_LARGE
```

Do not add speculative producers merely to preserve them.

Derive `MCP_SERVER_VERSION` from package metadata instead of duplicating `0.1.0`.
Make the optional MCP CLI fail with a clear “install constructicon[mcp]” message
when the extra is absent rather than a raw import traceback.

# Final elegance test

The follow-up is complete when these sentences are literally true:

> A caller can mutate Constructicon through one public object only. That object
> authorizes one actor, opens one command session, uses one typed immutable plan,
> applies or reconciles one domain fact, and stores one exact response.

> A caller can read a large record only through a reference that is authorized for
> that actor, identifies immutable canonical bytes, and verifies its digest before
> returning a chunk.

> A page sequence is a projection of one exact store revision. New writes can be
> seen by a new query, never by changing the meaning of an old cursor.

> `RunHost` owns coroutines and nothing else. It does not schedule graph units,
> cache domain results, swallow hard death, or strand recoverable runs.

The compressed M6 shape remains:

```text
Authenticate
→ Claim
→ Plan
→ Apply once
→ Record
→ Reference
→ Retry
→ Replay
```
