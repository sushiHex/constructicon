# PR B — M6.2 internal compression

PR B begins only after PR A and post-merge `main` are green.

## B1. Make registry pagination revision-correct

Add one immutable registry revision:

```python
class RegistryRevision(BaseModel):
    registration_seq: NonNegativeInt
    promotion_seq: NonNegativeInt
```

`RegistrySnapshot` records the revision that produced it. `RegistryStore` gains a
historical read at an exact retained revision; no new table is required because
component registrations and promotions are append-only and already sequenced.

All registry pages bind the first page's revision:

- versions page uses the registration upper sequence;
- candidates page also pins the stable version at that promotion revision;
- reverse dependencies are computed from the exact historical snapshot;
- comparison and impact data use one snapshot, never two current reads.

Cursor continuation carries the registry revision, not merely list length.

Tests:

- registering a version between pages does not enter the old sequence;
- promoting a new stable between candidate pages does not shift or duplicate rows;
- changing a composite between rdeps pages does not alter the old closure;
- a new query observes the new registry revision.

## B2. Calibrate cursor integrity honestly

Do not introduce key-management machinery merely to make cursors look like
security tokens. They are continuation data, and every read independently checks
actor authority.

- Rename `check` to `checksum`.
- Document it as accidental-corruption detection, not authentication or proof.
- Keep actor, endpoint, query, and revision validation.
- Validate every continuation bound against an actual store revision or maximum.
- Use exact schema literals.
- Remove “tamper-evident” language wherever it appears.

A future distributed/public deployment may add an injected HMAC signer with its
first real key-management consumer; M6.2 does not build one prematurely.

## B3. Remove private walker reach-through

Promote the runtime operations M6 genuinely needs into explicit internal methods:

```python
Walker.load_manifest(run_id)
Walker.materialize_run(run_id)
```

`Constructicon` delegates to those methods rather than calling `_load_manifest`
and `_materialize`.

Do not move materialization into the control layer; it is execution semantics and
belongs with the walker.

## B4. Split `ControlPlane` by responsibility without adding public concepts

Retain one public `ControlPlane` facade. Internally compose exactly two concrete
private collaborators:

```text
_ControlQueries    bounded reads, pages, details
_CommandExecutor   command sessions and domain mutations
```

No protocols, no plugin registry, and no generic operation dispatch table.
`ControlPlane` remains the only public name and delegates each method once.

Target outcomes:

- `api/control.py` becomes a small facade and lifecycle owner;
- command law exists only in `_control_commands.py`;
- paging and summaries exist only in `_control_queries.py`;
- detail authorization/addressing remains in `detail.py`.

## B5. Rename SQLite internals by enduring responsibility

Keep one concrete public `SqliteJournal`, but remove milestone-history names:

```text
sqlite_legacy.py          → _sqlite_execution.py / responsibility-based facets
_sqlite_v5_control.py     → _sqlite_control.py
_sqlite_v5_reads.py       → _sqlite_queries.py
_sqlite_v5_schema.py      → _sqlite_schema.py
```

Recommended permanent decomposition:

```text
_sqlite_base.py       connection, transaction, clock, fault probe
_sqlite_schema.py     schema creation and versioned migrations
_sqlite_execution.py  runs, events, checkpoints, effects, leases, attestations
_sqlite_registry.py   component versions and promotions
_sqlite_control.py    commands and approvals
_sqlite_queries.py    bounded read projections
sqlite.py             one concrete assembled class
```

Private mixins are acceptable implementation decomposition; version numbers and
“legacy” are not permanent concepts. Keep migrations explicitly version-named
inside `_sqlite_schema.py`.

Rename the migration test to `test_sqlite_v4_to_v5.py`.

## B6. Remove dead public contracts and duplicate naming

Remove or implement every public `ControlCode`. At the time of this review the
following have no producer and should be deleted rather than advertised:

```text
RUN_NOT_RESUMABLE
COUNTERFACTUAL_EFFECT_UNSUPPORTED
DETAIL_TOO_LARGE
```

Do not add speculative producers merely to preserve them.

Derive `MCP_SERVER_VERSION` from package metadata instead of duplicating `0.1.0`.
Make the optional MCP CLI fail with a clear “install constructicon[mcp]” message
when the extra is absent rather than a raw import traceback.
