**Scope:** preserve a panel's authored membership as ordered, explicit port

**Authority:** `docs/INVARIANTS.md` → `docs/ARCHITECTURE.md` → accepted ADRs →

This revision closes the four blockers in rev 3 without reviving general
connector liveness. A connection remains reachability and identity; a map is
the authored binding claim. The validator proves only the claim the graph
actually carries.

## 1. Round-five adjudication

The core of rev 3 survived review: a drifted member fails at the gather port,
an unchanged mapped fan-in produces byte-identical bindings, `sdk/wider`
inverts as predicted, and the architect-repair loop converges. Four surrounding
claims did not survive.

| Finding | Why it is real | Rev 4 decision |
| --- | --- | --- |
| Renaming the aggregator port discards every map | `_bind_node_inputs` iterates resolved inputs, so an explicit destination absent from that boundary is never visited | Every explicit destination is consumed exactly once or faults as `unused_map_destination` |
| A member may drift from cardinality `one` to `many` | `_source_matches` compares only nominal identity, so the selector still passes | Every explicit selector supplies one source whose source port has cardinality `one` |
| The counterfactual guarantee included retained old panels | A graph authored before this change has no maps to re-prove | The guarantee applies to mapped graphs only; history is not retrofitted |
| Schema decisions were deferred | Multi-map admission changes the accepted semantic subset of Graph schema 1, and a new strict description field breaks schema-1 readers | Graph remains schema 1; `SystemDescription` becomes schema 2 |

Three smaller corrections follow from the same review.

- The committed general-law generator is the defective first-pass instrument.
  Its JSONL and counts are withdrawn evidence, not the source of a conclusion.
- Rev 1's preserved `218 of 234` sentence conflicts with the withdrawn
  artifact's `219 of 234`. Neither number is authoritative. Rev 1 remains
  unchanged under the archive's immutability rule; this is its erratum.
- The panel boundary check is not simply removed. Its pool-based explanation
  becomes false after maps, but the two shapes it excludes remain invalid for
  truthful, local reasons stated in § 3.

The name changes with the scope. **M7.1 is panel membership.** Connector
liveness was measured, refuted, and remains rejected as a general admission
law.

## 2. The four laws

### A. A mapped `many` port is an ordered union of scalar selectors

Several incoming connections may map the same destination port when that port
has cardinality `many`. Their distinct selectors are evaluated in graph
connection order and concatenated in that order. Repeating an identical
selector is idempotent: its first occurrence fixes its position and later
occurrences coalesce.

A mapped port replaces magnetic selection, as it does today. It never combines
the explicit selectors with the upstream pool. An unmapped port keeps the
current magnetic rules byte for byte.

A port of cardinality `one` or `optional` admits exactly one distinct selector.
The existing duplicate-destination refusal moves to the place where the
resolved destination cardinality is known.

### B. Every map is accounted for

Each `Connection` still names known source and destination nodes. Inside a
known destination, every map key must name an input on that destination's
resolved boundary. Admission refuses an unknown endpoint before compilation and
an unused map destination while binding the resolved component. No entry may
fall out because the validator happened to iterate a different set.

The exact location travels with the map while it is validated: connection
index, destination node, destination port, and the retained definition path
when compilation is inside a composite. The validator does not collapse maps
into a destination dictionary before that provenance has done its job.

### C. An explicit selector names one scalar producer

Every selector used by `Connection.map` must resolve to exactly one source, and
that source port must have cardinality `one`. Nominal identity and source
cardinality are both part of the explicit binding boundary.

Destination cardinality does not flatten a producer. A destination of
cardinality `many` is a fan-in of scalar selectors, not permission to import a
`many` producer's internal collection. An `optional` producer likewise cannot
stand for one panel seat. Authors who need either shape compose an explicit
adapter that emits one value.

This rule is deliberately limited to explicit maps. Magnetic binding retains
its present handling of graph inputs, composite outputs, and transitive pools.
It also deliberately narrows one shape the current validator admits: a single
explicit selector from a `many` or `optional` source. That shape has no defined
flattening or absence law and cannot represent one panel seat. Implementation
must inventory retained definitions and the repository corpus before landing;
the planning-base search found no `$input` selector and no mapped non-scalar
source. An external author using the accidental behavior must insert a scalar
adapter and re-admit rather than receive an inferred conversion (I5).

### D. `panel()` writes the claim it proves

For each member connection, `panel()` writes:

```python
map={gather_port: f"{member_id}.{member_result_port}"}
```

The connections' order is the seats' order. The direct `Graph` spelling carries
the same maps and remains byte-equal to the SDK spelling.

The authoring proof is local and complete:

1. every member has exactly one input and one output, both cardinality `one`;
2. every member has the same exact request boundary and result boundary;
3. the request and result nominal contracts differ;
4. the atomic aggregator has exactly one `many` input matching the member
   result contract; and
5. no other aggregator input has that nominal result contract.

Rules 3 and 5 replace the obsolete pool-hazard explanation. An echo member
does not express a question followed by a distinct answer, and a result-typed
policy input makes the aggregator's gather role non-unique. Both remain refused
for those reasons even though a mapped gather would ignore the boundary pool.

## 3. One representation inside admission

The implementation should preserve the IR's ordering rather than recover it
after loss. `_explicit_maps` becomes an ordered collection of private map-entry
records instead of a nested destination dictionary. Each record carries its
connection index, destination node and port, and selector. Identical selectors
for one destination coalesce only after their first position is fixed.

One binding helper serves ordinary graph nodes and Loop bodies:

1. partition the entries for the node by destination port;
2. compare that destination set with the resolved input boundary and emit a
   fault for every unused destination;
3. resolve each distinct selector in connection order;
4. require one scalar source per selector;
5. compare nominal identity with the destination port; and
6. enforce the destination cardinality before producing one
   `ResolvedPortBinding`.

This is private compiler state, not a new L0 contract. There is one validator
implementation and two call sites; a new public abstraction would add a noun
without a second owner. The walker receives the same manifest and decides
nothing new (I6, I10).

## 4. Fault contract

No `AdmissionCode` or fault-model version is added. Existing codes retain their
meaning; the new facts are carried by framed details where an exact coordinate
is required.

| Event | Code | Required identity |
| --- | --- | --- |
| Connection names an absent node | `graph.contract.invalid` | `unknown_connection_node`, connection index, ordered missing endpoint roles, exact graph or retained-definition coordinate |
| Map names no input on the resolved destination | `graph.contract.invalid` | `unused_map_destination`, connection index, destination node and port, exact graph or retained-definition coordinate |
| Selector names no source, several sources, or a non-`one` source | `graph.port.contract_mismatch` | selector, source cardinality or resolved count, destination port |
| Selector's nominal contract differs from the destination | `graph.port.contract_mismatch` | selector and both nominal contracts |
| More than one distinct selector maps a `one` or `optional` destination | the existing duplicate-map legacy refusal | destination port and selectors in deterministic order |

`_classify_fault` must recognize the cardinality wording as the existing port
contract mismatch rather than let it fall through to legacy. A proposal-owned
fault uses `AdmissionFault.path`. A retained nested definition uses framed
`{component, version, definition_path, connection_index}` details, because a
rendered scope is not injective and classification occurs against the root
proposal.

Refusal happens during admission. The same idempotency key can be reused after
the author repairs the graph; no run, manifest, command, or effect fact exists.

## 5. Counterfactual guarantee, stated exactly

A mapped source graph records its membership claim. Reproducing it under the
source lock resolves the same scalar member contracts. A counterfactual exact
override must preserve those contracts or admission refuses it with the
existing `COUNTERFACTUAL_LOCK_MISMATCH` projection and repair.

That guarantee starts with graphs authored after this change, and with any
hand-authored graph that already carries equivalent maps. A retained pre-change
panel has no map and therefore no durable membership claim. It continues to use
unmapped magnetic binding in reproduce and counterfactual modes. This work does
not infer maps from topology, rewrite retained graphs, or claim to detect its
lost member.

The limitation is permanent history, not a migration backlog. Manufacturing a
map for retained bytes would change their graph identity and pretend an old
author made a claim they did not record (I2, I3, I8).

## 6. Version decisions

### Graph remains schema 1

`Connection.map` already has exactly the required wire shape. This change
admits a previously rejected combination of existing values: several
connections mapping one `many` destination. An old validator rejects that new
graph rather than miscompiling it, so cross-version use fails closed. The graph
schema document and `source_graph_hash_for` domain remain version 1.

The scalar-source rule also rejects a previously admitted semantic combination.
That is a validation correction, not a wire migration: Graph schema 1 describes
the JSON shape, while admission owns whether a well-shaped graph satisfies the
current execution laws. The retained-definition inventory and a fixture for
the old shape make the compatibility cost visible; no retained bytes are
rewritten.

The alternative — bumping Graph for a semantic relaxation with no new syntax —
would fork the one graph language, cascade into every manifest reader, and
provide no additional safety. The changed authored panel gets a new
`source_graph_hash` naturally because its connections now contain maps.

### `SystemDescription` becomes schema 2

Truthful introspection must publish the new policy as a dedicated literal in
`BindingVocabulary`, not bury it in prose or append it to the unordered-looking
`resolution_order` tuple:

```python
mapped_many_policy: Literal["ordered_scalar_selector_union_replaces_pool"]
```

`DESCRIPTION_SCHEMA_VERSION`, `SystemDescription.schema_version`, the emitted
body, and the `system-description` digest domain all become 2 together. Graph
and admission `SchemaDocument`s inside the description remain at their own
current schema versions.

`SystemDescription` is strict. A schema-1 reader therefore rejects a schema-2
description and cannot silently ignore a binding law it does not understand.
There is no dual-write or compatibility parser: `describe()` is a current
authoring contract, not retained execution evidence.

### Other contracts are unchanged

`ExecutionManifest`, `ResolvedPortBinding`, `AdmissionFault`, SQLite, and the
registry schema do not change. For an unchanged fan-in, mapped and prior
unmapped compilation must produce byte-identical resolved bindings in the same
source order. Only the source Graph and its dependent manifest identity change
because the author wrote a new claim.

## 8. Required failure proof

### Map semantics

- two connections mapping one `many` destination bind the distinct selectors
  in connection order;
- reversing the connections reverses the resolved source order;
- repeated identical selectors coalesce at their first position;
- two distinct selectors on `one` and on `optional` retain the deterministic
  duplicate-map refusal;
- a mapped `many` port ignores compatible graph inputs and transitive pool
  sources;
- an unmapped equivalent remains byte-identical to its pre-change golden;
- ordinary nodes and Loop bodies use the same cases and outcomes.

### Total validation

- renaming the aggregator's gather port while retaining old map destinations
  fails as `unused_map_destination`; no selector is silently dropped;
- unused destinations fault at the root, in an inline nested Graph, in a Loop
  body, and in a retained nested composite, each with an exact coordinate;
- unknown source, unknown destination, and both unknown endpoint roles produce
  one deterministic endpoint fault per connection;
- a map whose selector resolves to a `many` or `optional` source fails as
  `graph.port.contract_mismatch` even when its nominal contract matches;
- a selector resolving to zero or multiple sources fails with the same code;
- the retained-definition and repository inventories contain no mapped
  non-scalar source; a fixture proves the old accidental shape now fails closed
  and names the scalar-adapter repair;
- every fault is exercised through public JSON admission and `runtime.admit`,
  not only a private preflight helper.

### Panel law

- a drifted member result contract fails at the mapped gather port;
- a member result drifting from `one` to `many` and from `one` to `optional`
  fails even with unchanged nominal identity;
- the same idempotency key succeeds after each member is repaired;
- a renamed or contract-drifted aggregator gather faults instead of discarding
  maps;
- the cross-port counterexample still fails at the gather map even when the
  drifted member could bind another aggregator input;
- an undrifted mapped panel and the old unmapped fan-in have byte-identical
  `ResolvedPortBinding` bytes and order;
- `sdk/wider` proves that bystander, compatible graph input, and transitive
  helper no longer widen a panel, while all three still widen an unmapped
  hand-authored gather;
- an echo member and a result-typed aggregator policy seed are refused by the
  exact authoring rules in § 2.D;
- SDK and literal Graph outputs are byte-equal, maps included;
- the real-process human panel lane completes with the mapped graph.

### Counterfactual and versions

- a newly authored mapped panel reproduces under its exact lock;
- an incompatible exact member override reports
  `COUNTERFACTUAL_LOCK_MISMATCH` and names the existing compatible-override
  repair;
- a retained pre-change panel fixture remains unmapped and exercises the
  documented limitation rather than acquiring invented exactness;
- `SystemDescription` round-trips only as schema 2 and its digest uses domain
  version 2;
- a strict schema-1 description model rejects the new document;
- the embedded Graph and admission schema documents remain version 1;
- `issue-to-summary`, `architect-selection`, `mapped-loop`, `diamond`, and
  `gathering` preserve their pre-change manifest bytes.

Mutation checks must remove each of: destination accounting, source-cardinality
comparison, connection-order preservation, panel maps, the request/result
distinction, the unique result-typed gather, and the schema-2 literal. Every
mutation must make a named proof red.

## 9. Research integrity

The general-law result rests on four named counterexamples, not a frequency.
`shadow_general_law.py` and `raw-general-law.jsonl` are retained as withdrawn
first-pass artifacts because deleting them would erase how the measurement was
corrected. They are not reproducible supporting evidence and must not be cited
as such. The corrected gather and provenance instruments remain usable within
their recorded limits.

Rev 1's `218 of 234` and the measurement record's later `219 of 234` describe
the withdrawn artifact and disagree. The immutable rev 1 file keeps its original
bytes. This revision supersedes both numeric claims; neither participates in
the decision or its proof.

## 10. Documentation and sequencing

The proposed [ADR 0017](../../adr/0017-panel-membership-is-an-authored-map.md)
records the policy decision. It remains proposed until this plan is approved.
Implementation does not become architectural authority before that decision.

- **PR A — authored membership.** Implement ordered explicit maps, total map
  validation, scalar source cardinality, panel authoring, schema-2
  introspection, and every proof in § 8 except endpoint coordinates.
- **PR B — connection endpoints.** Refuse unknown endpoints with framed exact
  coordinates across root, nested Graph, Loop, retained composite, and
  counterfactual paths.
- **Closure.** Update `ARCHITECTURE.md`, `CONTRIBUTING.md`, the M7 record, and
  the plan manifest to current truth only after the implementation lands.

The split is reviewable but not semantic: PR A must reject unused destinations
and PR B must reject unknown nodes. Neither may describe the map surface as
total until both are merged.
