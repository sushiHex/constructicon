# Constructicon M6.1 / M6.2 implementation handoff

> **Historical handoff:** This record was produced during the M6.1 recovery
> sequence against an earlier repository base. It preserves what was implemented
> and how the artifact was intended to be published. It is not current normative
> architecture and must not override later commits, PRs, ADRs, or
> `docs/ARCHITECTURE.md`.

## Durable project base at time of handoff

- Repository: `sushiHex/constructicon`
- Base branch: `main`
- Exact base commit: `2f0945c1dfb22635053d3cab1d0425b4357d90c7`
- Existing integration branch: `fix/m6-1-authority-and-green-main`
- That branch contained an older truncated patch payload and was not to be treated
  as the finished implementation.

## Completed implementation represented by the handoff

- shared command owner/admin authorization across status, detail, and MCP resource
  paths;
- bounded command summaries with full records only by immutable reference;
- required `DetailRef` digests, verified on every chunk read;
- no immutable command or result reference before addressed bytes settle;
- one typed private command session and typed immutable plan models;
- all eight mutations covered at after-plan, after-domain, and after-completion
  seams;
- `ControlPlane` as the public durable-mutation gateway;
- private lifecycle and implementation fields;
- bounded `RunHost` recovery, observable hard death, and no production result
  cache or wait API;
- exact registry revisions for versions, candidates, reverse dependencies, and
  comparisons;
- cursor `checksum` semantics calibrated as corruption detection, never authority;
- explicit walker manifest loading and result materialization methods;
- one small public `ControlPlane` over `_ControlQueries` and `_CommandExecutor`;
- responsibility-based SQLite modules instead of milestone-history names;
- dead control-code removal and package-derived MCP server version;
- optional-MCP installation guidance;
- removal of temporary M6 workflows, patch payloads, and source-export machinery;
- updates to architecture, ADR, agent, and contributor documentation.

## Publication procedure recorded by the handoff

On a clean checkout at the exact base commit, the patch and apply script were to
be placed together and invoked with:

```bash
./apply-constructicon-m6-1-m6-2.sh
```

The script was expected to:

1. refuse a dirty tree;
2. verify the exact base commit;
3. verify the patch checksum;
4. apply and stage the patch;
5. remove hidden temporary M6 payloads;
6. run `uv sync --dev`;
7. run `uv run verify`.

After a green gate, the instruction was to commit, push a fresh branch, open a PR,
and merge only after the resulting `main` commit passed the same gate.
