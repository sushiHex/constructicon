# Claude host session: staging package template

Preparation for [#283](https://github.com/sushiHex/constructicon/issues/283)
and [#40](https://github.com/sushiHex/constructicon/issues/40). This is not
private-host authorization. Accepted [ADR 0021](../../adr/0021-subscription-executors-bind-operator-stores.md)
did not itself authorize deployment or authentication; the owner's subsequent
authorization of steps 1-4 still requires an exact, reviewed host package and
its stop/recovery checks. The only composed step below is unprivileged staging.
It executes neither Claude nor a controller lane, but
the stager does run the fixed, root-owned host loader to enumerate dependencies.
Do not run these unreviewed package bytes or skip the exact-host gates.

## Package boundary

`scripts/m8_procedure_package.py` assembles the boot, guarded drift and `stage`
fences below into one
step file and writes its declared stdout expectation; it neither executes the
step nor checks its actual output. The merged source commit is
`41e416f48a08a7daae6f8d30f5904f1d48affcb7` (#286), including the
corrected #283 stage-source drift guard. The independently reviewed private
selection has SHA-256 `2035c40ea91f4d8712141a6f46ef6a7334e45325fde2a9f6db7fcbc19bc109eb`.
The boot and drift expectations remain private session values; `check
--template` checks composition, while normal `check` refuses the unfilled
values. Build a fresh package with the separately reviewed private `--values`
TOML for `EXPECTED_BOOT`, `DRIFT_STDOUT_HEX` and `DRIFT_TOOL_SHA256`; never
edit a generated step. A successful build is not host execution authority.

The private selection file must already exist at the fixed host input name
below, with exactly the schema accepted by `claude_host_artifacts.read_selection`:
model, effort, and login/observe/reload destination/address pins and finite
connection caps. Its separately reviewed SHA-256 is the second literal. No
account fact, credential, private address or raw host listing belongs in a
public issue or this file. A later selected-plan input remains an explicit,
separately reviewed choice for each session, not an inferred mode observation.
The concrete proposed selection is `claude-sonnet-4-6` with effort `low` and
total connection ceilings of 8 for login, 16 for observe and 8 for reload.
The model/effort pair is the pinned credential-free startup fixture's choice;
the ceilings allow for at most two observe initializations. Neither its
current upstream availability nor the sufficiency of these ceilings has been
measured for an authenticated session. A refusal is a stop, not permission to
widen the selection.

The stage owns a new `0700` workspace. A failed or dropped session may leave
`source.git`, archive, selection, report or partial staging. Preserve them;
absence of a success line is not proof of no work. No automatic rerun or
cleanup is authorized. Before any retry, establish current boot, drift,
exclusive operator custody and exact remaining paths under a separately
reviewed recovery command. There is no root write in this step. The reviewed
private selection must be placed at S1's fixed host name with owner-private
mode and that digest; its current local preparation path is not the host file.
The exact transport below creates the fresh private input and uploads only the
reviewed 424 LF bytes. S0 rechecks its directory, file owner, mode, link count
and hash before its first write. A failed or partial upload is a stop, never a
reason to reuse or overwrite the input directory.

## Fixed private input and package transport

Build the staging package with the separately reviewed private values before
transport. Its `MANIFEST.sha256` contains only `claude-stage.sh` and
`claude-stage.expected.json`; independently review and record the complete
manifest digest and generated bytes. The private local `PACKAGE_DIR`,
`LOCAL_SELECTION`, `SSH_TARGET` and `SSH_HOST_KEY_ALIAS` are exact reviewed
inputs, not inferred from this public document. Run this local Git Bash fence
only with those inputs bound and a separately reviewed private local package
directory. Its path must have canonical absolute Git Bash spelling and no
symlink component; this syntactic check does not establish Windows ACL custody.
The remote preflight is read-only: it requires a
canonical operator-owned home under root/operator-owned, non-group/other-
writable ancestors and absent fixed destinations. No host write precedes it.

The SFTP batch uses fixed home-relative names and stops on a failed fresh
`mkdir`; there is no retry or overwrite fallback. It creates both private
directories, places the selection, then sets its mode to `0600`. The staged
Bash file and manifest travel by SCP into the fresh package directory. Before
Bash, the remote command compares the manifest to its independently reviewed
digest and verifies every listed file. The local wrapper retains the two
streams and requires empty stderr and the exact package-declared three stdout
lines before treating the step as complete. SSH execution has closed stdin;
no script is pasted or streamed to the host. BatchMode, strict host-key checking
and the previously recorded host-key alias apply to every transport command.
`SSH_TARGET` must identify the exact operator account and host. A partial
transport stops for exact-path recovery review. The `4096`-byte stdout test is
an after-the-fact verdict bound, not a streaming disk cap; `ConnectTimeout`
bounds connection setup, not the full stage. Do not infer a finite full-session
deadline from either check.

```bash
set -Eeuo pipefail -C
umask 077
: "${PACKAGE_DIR:?Reviewed fresh local package directory required}"
: "${LOCAL_SELECTION:?Reviewed private selection path required}"
: "${SSH_TARGET:?Reviewed operator target required}"
: "${SSH_HOST_KEY_ALIAS:?Recorded host-key alias required}"
: "${MANIFEST_SHA256:?Independently reviewed manifest digest required}"
SELECTION_SHA256=2035c40ea91f4d8712141a6f46ef6a7334e45325fde2a9f6db7fcbc19bc109eb
[[ "$MANIFEST_SHA256" =~ ^[0-9a-f]{64}$ ]]
[[ "$SELECTION_SHA256" =~ ^[0-9a-f]{64}$ ]]
case "$PACKAGE_DIR" in /*) ;; *) exit 1 ;; esac
test -d "$PACKAGE_DIR"
test ! -L "$PACKAGE_DIR"
test "$PACKAGE_DIR" = "$(cd "$PACKAGE_DIR" && pwd -P)"
test ! -e "$PACKAGE_DIR/selection.json"
test ! -L "$PACKAGE_DIR/selection.json"
test ! -e "$PACKAGE_DIR/input.batch"
test ! -L "$PACKAGE_DIR/input.batch"
test -f "$PACKAGE_DIR/claude-stage.sh"
test -f "$PACKAGE_DIR/claude-stage.expected.json"
test ! -e "$PACKAGE_DIR/claude-stage.stdout"
test ! -L "$PACKAGE_DIR/claude-stage.stdout"
test ! -e "$PACKAGE_DIR/claude-stage.stderr"
test ! -L "$PACKAGE_DIR/claude-stage.stderr"
test "$(/usr/bin/wc -c < "$LOCAL_SELECTION")" -eq 424
test "$(/usr/bin/sha256sum "$LOCAL_SELECTION" | /usr/bin/cut -d ' ' -f 1)" = "$SELECTION_SHA256"
test "$(/usr/bin/sha256sum "$PACKAGE_DIR/MANIFEST.sha256" | /usr/bin/cut -d ' ' -f 1)" = "$MANIFEST_SHA256"
(cd "$PACKAGE_DIR" && /usr/bin/sha256sum --check --strict --quiet MANIFEST.sha256)
/usr/bin/cat "$LOCAL_SELECTION" > "$PACKAGE_DIR/selection.json"
/usr/bin/printf '%s\n' \
  'mkdir m8-claude-input' \
  'chmod 700 m8-claude-input' \
  'put selection.json m8-claude-input/selection.json' \
  'chmod 600 m8-claude-input/selection.json' \
  'mkdir m8-claude-stage-package' \
  'chmod 700 m8-claude-stage-package' > "$PACKAGE_DIR/input.batch"
OPTS=(-o BatchMode=yes -o StrictHostKeyChecking=yes
  -o "HostKeyAlias=$SSH_HOST_KEY_ALIAS" -o ConnectTimeout=15 -o LogLevel=ERROR)
ssh -T "${OPTS[@]}" "$SSH_TARGET" \
  "/usr/bin/python3 -I -S -B -c 'import os,pathlib,stat,sys; h=pathlib.Path(os.environ[\"HOME\"]); u=os.geteuid(); ok=(u!=0 and h.is_absolute() and h==h.resolve(strict=True) and h.stat().st_uid==u and all(stat.S_ISDIR(s.st_mode) and s.st_uid in (0,u) and not s.st_mode & 0o022 for s in (p.lstat() for p in (h,*h.parents))) and not os.path.lexists(h/\"m8-claude-input\") and not os.path.lexists(h/\"m8-claude-stage-package\") and not os.path.lexists(h/\"m8-claude-stage\") and not os.path.lexists(h/\"m8-claude-drift-stage\")); sys.exit(0 if ok else 1)'" < /dev/null
(cd "$PACKAGE_DIR" && sftp -b input.batch "${OPTS[@]}" "$SSH_TARGET" < /dev/null)
scp "${OPTS[@]}" "$PACKAGE_DIR/claude-stage.sh" \
  "$PACKAGE_DIR/claude-stage.expected.json" "$PACKAGE_DIR/MANIFEST.sha256" \
  "$SSH_TARGET:m8-claude-stage-package/" < /dev/null
ssh -T "${OPTS[@]}" "$SSH_TARGET" \
  "cd \"\$HOME/m8-claude-stage-package\" && test \"\$(/usr/bin/sha256sum MANIFEST.sha256 | /usr/bin/cut -d ' ' -f 1)\" = '$MANIFEST_SHA256' && /usr/bin/sha256sum --check --strict --quiet MANIFEST.sha256 && /bin/bash claude-stage.sh" \
  < /dev/null > "$PACKAGE_DIR/claude-stage.stdout" 2> "$PACKAGE_DIR/claude-stage.stderr"
test ! -s "$PACKAGE_DIR/claude-stage.stderr"
test "$(/usr/bin/wc -c < "$PACKAGE_DIR/claude-stage.stdout")" -le 4096
/usr/bin/printf 'boot-checked\ndrift-checked\nclaude-stage-recorded\n' |
  /usr/bin/cmp -s - "$PACKAGE_DIR/claude-stage.stdout"
```

## S0: fixed boot and guarded private drift before stage

The owner supplies the exact boot UUID and the installed drift tool's digest
and expected complete stdout from separate private review. The existing
package builder fills only those three typed values as read-only shell
variables. The exact G1 guard captures both streams, exit status and the
whole expected output; a bare drift invocation is forbidden. This is a check
of the retained host baseline, not qualification of new Claude artifacts.
The D2 fresh-boot verifier and probe in
`M8-N4-launch-replacement.md` LR2 remain separate prerequisites under their
own exact installed commit and workspace. The retained-store LR1 reboot
anchor is not reinterpreted for a new Claude store.

```bash
set -Eeuo pipefail
umask 077
C=41e416f48a08a7daae6f8d30f5904f1d48affcb7
SELECTION_SHA256=2035c40ea91f4d8712141a6f46ef6a7334e45325fde2a9f6db7fcbc19bc109eb
test "$(/usr/bin/id -u)" -ne 0
[[ "$C" =~ ^[0-9a-f]{40}$ ]]
[[ "$SELECTION_SHA256" =~ ^[0-9a-f]{64}$ ]]
: "${HOME:?}"
W="$HOME/m8-claude-stage"
I="$HOME/m8-claude-input"
S="$I/selection.json"
/usr/bin/python3 -I -S -B -c '
import os, pathlib, stat, sys
home, input_dir, selection, workspace = map(pathlib.Path, sys.argv[1:])
uid = os.geteuid()
if not (home.is_absolute() and home == home.resolve(strict=True)
        and input_dir == home / "m8-claude-input"
        and selection == input_dir / "selection.json"
        and workspace == home / "m8-claude-stage"
        and not os.path.lexists(workspace)):
    sys.exit(1)
for parent in (home, *home.parents):
    info = parent.lstat()
    if not (stat.S_ISDIR(info.st_mode) and info.st_uid in (0, uid)
            and not info.st_mode & 0o022):
        sys.exit(1)
if home.stat().st_uid != uid:
    sys.exit(1)
info = input_dir.lstat()
if not (stat.S_ISDIR(info.st_mode) and info.st_uid == uid
        and info.st_mode & 0o777 == 0o700):
    sys.exit(1)
info = selection.lstat()
if not (stat.S_ISREG(info.st_mode) and info.st_uid == uid
        and info.st_nlink == 1 and not info.st_mode & 0o077):
    sys.exit(1)
' "$HOME" "$I" "$S" "$W"
test "$(/usr/bin/sha256sum "$S" | /usr/bin/cut -d ' ' -f 1)" = "$SELECTION_SHA256"
EXPECTED_BOOT=UNREVIEWED
[[ "$EXPECTED_BOOT" =~ ^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$ ]]
test "$(/usr/bin/cat /proc/sys/kernel/random/boot_id)" = "$EXPECTED_BOOT"
/usr/bin/printf 'boot-checked\n'
```

## S1: fetch pinned inputs and stage, operator only

This is a single future noninteractive private-host step. Its output line is
only a framing fact; review the private `stage.json`, exact
`staging/constructicon-m8-claude/launch-config.json` bytes and the host facts
separately. The helper independently checks that its running bytes are the
commit's blob, that commit is on fetched main's first-parent line, the pinned
vendor archive/member and the source/host custody rules. The explicit archive
URL and SHA below match the committed hosted download and the production
helper's fixed pin; the hosted fixture is never executed on the host.
Before extracting or executing that helper, this step also checks the exact
`100644 blob` tree entry and a finite blob-size bound. S0 checked custody
before the drift capture made any write.

## Review boundary after S1

Stop after staging. The stager's `launch_config_sha256` is an observation, not
its own authorization. A second reviewer must independently inspect the exact
configuration bytes and compute its SHA-256; inspect the staged whole-tree
inventory, pinned archive/member, runtime closure, bubblewrap, policy and ABI
identities; reconcile the host boot/drift and retained controller/store facts;
and approve a literal hash and scoped installation/recovery commands. An
unexpected value stops. The pinned C above includes the #286 fix; the
host-derived runtime/configuration digest is not invented here.

The next package is not composed here. Its required command order is: prove
the installed controller at the exact commit (reuse the controller-only
`controller-wheels`, `stage-controller`, `judge-controller`, `verify-controller`
law if a fresh or separately approved replacement is necessary); perform an
isolated service-user import check including `claude_lane`,
`claude_maintenance_session` and `claude_native`; feed a fresh kernel profile
listing to `claude_host_artifacts judge` with the independently reviewed literal
configuration SHA; only after `ready: true`, copy the one fresh Claude tree,
explicitly set its full ownership to root, install the fixed policy and load
the three profiles with stock root tools; then capture a new profile listing
and run `verify` independently of staging. No existing Codex launch set or
operator store is a copy source or deletion target. Any partial root prefix
requires exact-path inventory and separately approved recovery, not retry.

Only after `installed: true`, controller verification, benign launcher probe
and fresh custody checks may a separately authorized attended login command
be considered. It uses the existing isolated controller bootstrap
`/usr/bin/python3 -I -S -B -c` with only
`/opt/constructicon-m8-controller` inserted in `sys.path`, invoking
`operator_store maintain -- ... claude_lane login`; the root helper supplies
the inherited custody. `--first-login` needs explicit credential-file creation
authority. A later `observe --selected-plan SELECTED_PLAN` is a separate fresh
maintenance acquisition, never an automatic continuation. The Codex-specific
lane allowlist and the five session-value shapes in
`m8_procedure_package.py` do not review or fill Claude lane/hash commands;
they cannot turn these deferred words into an executable second package.
