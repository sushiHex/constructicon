## Outcome and boundary

The Python change-review entry compares exact committed blobs with a bounded AST
analysis. Only the Git references and structured report enter the graph, which
composes an advice request with the existing human-advisor component, mailbox
and durable control plane. Source is never imported or executed. The scripted
demo is
explicitly operator advice, not a model review, test execution, security judgment
or merge approval. Exact component versions avoid moving stable pointers.
Separate submit, reply and status invocations expose the retained run across
processes; command keys retain their existing replay/conflict semantics.

Metering remains the existing schema-3 public result, with bounded detail and
provenance. No new accounting API or fabricated price is introduced. This
deterministic workflow has no native dispatch observations; unknown estimated
cost and confirmed charge remain unknown. Existing fake-peer native tests use
the actual adapter/journal/public projection to exercise observations without
vendor calls. They are not observations from a live account.

The [preparation census](../../operator-preparation.md) names the supported
entries and their source/execution limits. The actual M9 fake transport checks
distinct exclusive phase staging, execution/readback agreement and occupied
later-phase refusal before copying or execution. Fake phase responses do not
prove arbitrary shell semantics. Historical OBSERVE, recovery and standalone
controller preparation remain outside that whole-composition proof; #308 stays
open. Frozen shell blocks and stopped private packages are unchanged.

The [quality-comparison packet](M9-quality-comparison-preparation.md) retains
the earlier fixed paired protocol and makes prerequisites explicit. Independent
exam review/sealing, a minimal reviewed live assembly and a separate exact
execution/cost decision still precede any experiment. The completed M9 lifecycle
does not establish real-answer quality or authorize additional calls.

The CI selector adds only the already-reviewed living
`M9-live-selector-record.md` filename to its closed prose set. Unknown sibling
paths, the operator runbook and executable mode remain on full CI. This change
does not reclassify this code-bearing delivery as prose or bypass any required
check.

Independent final-candidate review classified four introduced, non-blocking

checked alongside the unchanged replay/recovery path.
Follow-up source review also identified partial-clone lazy fetching as a path
from an otherwise read-only Git operation to a transport. The helper now sets
the documented empty protocol allowlist and disables lazy fetching. A real
local-only admitting fetch control and the same helper's refusal check that
repository-level protocol permission cannot enable transport. No network or
vendor call is needed for this proof.

The suggestion to trigger an additional connector review solely because the

sufficient independent review covering the final head. The PR records the
connector's actual reviewed revision separately from final independent review;
neither an old review nor an old CI run is represented as final-head evidence.

No vendor binary, credential, model call, VM operation, controller installation,
re-baseline or production deployment is part of this delivery.

## Repeatable offline preparation and batch usage — #461

The next offline wave follows #460 without another quality experiment. It
extends the existing READ operator with `prepare-input` and adds a small batch
projection over the existing protected reply collector. The graph, actor,
grants and metering journal/schema remain unchanged. No executor or package

preparation and observation, not live authority.

### Input production and composed evidence

The caller independently pins a canonical template and a prior schema-3
selection, and identifies that completed window's custody/record/packet. The
existing collector reconstructs the accepted reply. The new reader derives the
qualification directory from the prior selection digest, reconstructs the
producer's exact qualification packet and identity, and compares their hashes
with the window challenge. It checks completed capture statuses and empty
stderr, matching boot and generation, selected cleanup source/bindings/script,
locked withdrawal readback and the supervisor's withdrawal/park receipt hashes.
The park receipt also reproduces the existing VM-usage parser's idle result.
An active window or suspension blocks preparation.

Only `previous_boot`, `previous_generation`, `prior_session` and `prior_label`
are derived. Every other template field remains opaque and unchanged. All
validation precedes an exclusive binary file claim; canonical LF output is
read back and identified by digest. Existing/interrupted output is retained,
never resumed or overwritten. Both this action and existing `--preflight`
write binary JSON to stdout, avoiding Windows text newline translation.
Neither step grants a slot, compiles a package or measures current host facts.
The actual compiler and preflight remain separate steps; current custody,
boot, generation, installation and model authority still require their own
selected live scope and observations.

The accepting tests use the actual committed-source packet producer and a
complete fake-platform native window, including the real constructor,
supervisor, guest command/closure and teardown. Those retained outputs feed
the public writer, then a fixture compiler using real `assemble` and D2
producers, then the actual constructor/approval preflight twice with external
process calls denied. Exact refusal checks cover altered source, incomplete
or mistyped completion, qualification/candidate mismatch, withdrawal and park
evidence, active/suspension markers, canonical input bounds and occupied
output. Genuine `TextIOWrapper` streams configured for CRLF translation test
the binary stdout boundary portably. This fixture proves composition, not
arbitrary historical shell semantics or physical host containment.

### Batch metering semantics

`change_review_batch_report.py` accepts one to 32 custody/record/packet triplets.
Every triplet passes the existing collector, including duplicates. A repeated
canonical custody/record pair contributes once only when the complete reply
and exact packet fingerprints agree. Different windows count separately even
when deterministic RunIds match: their fresh journals are different native
attempts. Conflicting duplicates refuse rather than selecting a convenient
cut. No new store or accounting API is introduced.

The bounded 32 KiB JSON view excludes advice, private paths and detail URIs.
It retains per-window native metering values and immutable event cuts, counts
coverage separately, and sums only source-scoped known token subtotals. An
unknown axis stays null and an observed zero stays zero. Recorded attempts are
not backend requests. The existing monetary contract permits no known amount;
estimate and confirmed charge therefore remain null/unknown. Timing is
null/unavailable because durable run-result metering retains no elapsed value.
No prices, subscription balance, monetary ceiling or backend count are inferred.

The real historical CLI check supplied all three #459 windows plus the first
window again. Its 2,728-byte report counted four inputs, three unique windows,
one duplicate and three recorded attempts, with exactly 18,366 known input /
554 known output tokens under `codex_fresh_thread_total_v1`. Money, elapsed time
and backend requests remained unknown. No raw advice or private path appeared.

The tests also exercise two genuine fake-platform windows with the same RunId,
partial counters, observed zero, legacy/unmeasured/unavailable coverage,

actual CLI. An initial fixture reused a permanently closed acquisition across

## Durable explicit-file batches — #463

### Composition and durable identity

`examples.change_review_batch` accepts one to sixteen distinct canonical paths
at exact before/after commits. Every committed blob passes the existing source
boundary and analysis before the entry opens application state. The root Graph
contains inline copies of the existing single-file graph with renamed boundary
ports and exact existing component pins. It adds no primitive, scheduler,
workflow representation, store or accounting API.

A file identity binds canonical repository and path, independently of commits
or batch position. A single caller start key binds the complete graph and
inputs: reordered identical paths replay; a changed batch conflicts. Replies
select retained member identities and delegate through `ControlPlane` as the
fixed local actor. Public sealed inputs and manifest reconstruct membership
even when a start command is prepared before `RunStarted`. Canonical channel
identity functions address requests directly, without scanning inbox history.
Request payloads must positively match the retained per-file input. Status
starts no workers, performs no Git reads and never reconciles a command.

### Truthful projection and acceptance

The response preserves the producer's complete V3 result, including root
metering and its accounting cut, exactly once. Per-file usage remains unknown;
no division, multiplication, invented zero cost or price calculation occurs.
Sealed preflight analysis is distinguished from completed output. A retained
request alone means awaiting advice, not a positive parked checkpoint. Explicit
child completion and failure survive a failed/cancelled root; other unfinished
children become not completed. Advice from a completed sibling remains visible.

The public response limit is 256 KiB including its final LF. Payload omission
sets partial/limitation/per-file omission markers and preserves the root result;
metadata that still exceeds the limit refuses. Public detail reads have a 4 MiB
cumulative bound. Binary UTF-8 stdout avoids Windows CRLF expansion breaking
the advertised byte bound.

Focused tests exercise real Git and fresh CLI processes, reordered replay,
changed-batch and reply conflicts, file/request association, source nonexecution,
syntax-error facts, prepared-start recovery and three reply crash seams. Fault
proofs distinguish the retained plan, domain mutation and completed command;
status remains observational at each seam. Bounds bind in the fixtures, and a
real CRLF-translating text wrapper exercises the output boundary. The documented
two-file clean-checkout walkthrough also ran successfully, including final root
success, replay and unknown monetary usage.

The first implementation assumed a child checkpoint meant the root had settled.
The final-reply accepting test disproved that assumption; shutdown could abandon
a still-running root. The reply observer now joins root settlement. Existing
parked-run cancellation semantics were preserved after a fixture incorrectly
assumed parked cancellation was available; the actual cancellation test uses a
fresh running run before its first park. Prepared-command completion is also
distinguished from replay of an already committed response.

The maximum-size probe exposed another application assumption: the single-file
15-second wait did not support sixteen children. A continuation observed healthy
progress through fourteen children at 180 seconds without a node failure.
Repeated synchronous summary/detail rendering competed with the worker: a
public summary query took about 3.45 seconds on that fixture, versus about
0.49 seconds for the existing public run-state query. No kernel guard was
weakened and no new caching/store layer was introduced.

Settlement now polls the existing public run-state query with a one-second
pause between iterations and one shared 180-second budget for submit and reply. Reply
also requires its positive child checkpoint before accepting a parked root.
The admitted manifest is loaded through the existing public system query once,
bounded and checked against the public run summary's seals, rather than
re-rendered for every detail page. The timeout response retains the exact root
result and submission/reply receipt, marks partial/timed-out, and exits 2.
Same-key recovery remains available; no cancellation, new run or automatic
mutation retry is introduced. The polling budget is not a command wall-time
guarantee because synchronous projection and shutdown have their own cost.
Maximum-size lifecycle timing and final-head CI receipts belong in the delivery
PR; these measurements are application observations, not a kernel performance
guarantee.

The actual maximum-size submit returned exit 0 with all sixteen inspections
completed and all sixteen advisor requests parked, a 37,640-byte response and
309.1 seconds of CLI wall time. The first fresh-process reply retained its
advice and returned the explicit timeout response after 416.6 seconds of CLI
work. Remaining replies were recorded through one public control-plane process
to avoid repeating the same expensive restart proof fifteen times.

That accepting path exposed a pre-existing `RunHost` starvation defect. All
fifteen remaining requests positively had canonical replies; the latest parked
wait and current journal event fence both equalled 148, with no owner or lease.
The explicit reply cause differed from the scan's first answered cause. At the
same fence, `launch()` correctly rejects a different cause, but its wake flag
could make the pump repeat synchronous scans without yielding to an already
created worker. Missing replies, a newer event fence and a held lease were
independently ruled out. Owning-process pump health was not directly observed;
the source premise was then reproduced with the existing host test doubles.

The bounded regression recorded eight consecutive scans with zero attempts or
worker starts on old source, then failed an assertion after a synchronous scan
guard released the loop. A mere async timeout cannot bound a non-yielding loop.
The minimal fix adds one cooperative yield between pump rounds. It changes no
cause selection, event fence, command, authority or graph scheduling law, and
all 24 affected host tests pass. Independent review covers this exact delta;
the retained sixteen-file run supplies the final real-journal recovery proof.
The earlier head's full CI passed but does not qualify the later host change;
new final-head CI receipts belong in the delivery PR. Projection and restart
latency are separately tracked in #465, without a cache or validation bypass.

This delivery is credential-free operator advice, not native model review or
evidence that generated advice improves coverage. It changes no VM, account,
credential, controller, qualification, accepted plan, production provider or
stable component pointer. Broader historical preparation remains in #308 and
the paired native-review quality limit remains in #459.
