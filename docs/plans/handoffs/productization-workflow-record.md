## Outcome and boundary

The Python change-review entry compares exact committed blobs with a bounded AST
analysis. Only the Git references and structured report enter the graph, which
composes an advice request with the existing human-advisor component, mailbox
and durable control plane. Source is never imported or executed. The scripted
demo is
explicitly operator advice, not a model review, test execution, security judgment
or merge approval. Exact component versions avoid moving stable pointers.
Separate submit, reply and status invocations expose the retained run across
processes; command keys retain their existing replay/conflict semantics.

Metering remains the existing schema-3 public result, with bounded detail and
provenance. No new accounting API or fabricated price is introduced. This
deterministic workflow has no native dispatch observations; unknown estimated
cost and confirmed charge remain unknown. Existing fake-peer native tests use
the actual adapter/journal/public projection to exercise observations without
vendor calls. They are not observations from a live account.

The [preparation census](../../operator-preparation.md) names the supported
entries and their source/execution limits. The actual M9 fake transport checks
distinct exclusive phase staging, execution/readback agreement and occupied
later-phase refusal before copying or execution. Fake phase responses do not
prove arbitrary shell semantics. Historical OBSERVE, recovery and standalone
controller preparation remain outside that whole-composition proof; #308 stays
open. Frozen shell blocks and stopped private packages are unchanged.

The [quality-comparison packet](M9-quality-comparison-preparation.md) retains
the earlier fixed paired protocol and makes prerequisites explicit. Independent
exam review/sealing, a minimal reviewed live assembly and a separate exact
execution/cost decision still precede any experiment. The completed M9 lifecycle
does not establish real-answer quality or authorize additional calls.

The CI selector adds only the already-reviewed living
`M9-live-selector-record.md` filename to its closed prose set. Unknown sibling
paths, the operator runbook and executable mode remain on full CI. This change
does not reclassify this code-bearing delivery as prose or bypass any required
check.

## Evidence and dispositions

Focused tests exercise the public example entry and fresh processes, supported
M9 qualification composition, metering result/detail boundaries and CI scope.
Final-head broad CI and independent review receipts belong to the delivery PR;
platform skips do not establish Linux containment.

Source inspection found that metering functionality was already present under
ADR 0024. Integration and truthful rendering were the needed work, rather than
another accounting facility. The initial example passed source text in graph
inputs; I5 requires code references, so analysis moved to the trusted local
entry and graph payloads retain exact GitRefs instead. Review also found the
first quality packet
abbreviated the earlier proposal's concrete interruption and whole-experiment
stop rules; those prerequisites were restored. Broad #308 completion was
rejected as an unsupported claim: a historical source packager does not prove
every downstream transport's output ownership.

Self-review found that the forwarded report initially advertised an opaque
second output contract. It now reuses the input's actual schema under the output
port name; the permitting entry test validates the emitted payload against that
published shape. This required a fresh focused run and final-head CI.

No vendor binary, credential, model call, VM operation, controller installation,
re-baseline or production deployment is part of this delivery.
