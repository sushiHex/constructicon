# M8 post-q12: preparation decision and evidence boundary

This is an additive decision record under [#186](https://github.com/sushiHex/constructicon/issues/186).
It does not change the bytes of the [post-q12 review](M8-post-q12-review.md)
or authorize a host session. The owner accepted the recommended offline wave
on 2026-10-18; its scope is recorded in the
[decision comment](https://github.com/sushiHex/constructicon/issues/186#issuecomment-6247008604).

## Decision

The experiment's goal is **autonomous operation**, not merely obtaining the
candidate data file. Preparation is limited to one q13 procedure and its
rehearsal. The proposed execution ceiling is one further live session and one
application attempt, with a separate owner go on the exact reviewed procedure
still required. A dispatched or uncertain dispatch consumes the attempt.

Another output-contract stop requires reconsidering the procedure contract;
it does not authorize an automatic q14 or removal of a check. A second normal
application non-acceptance reopens the task, model and exam before a third
attempt is proposed. There is no outside-Constructicon prompt diagnostic in
this wave. Such a run would not establish the historical inside-graph cause.

This decision authorizes source-only preparation and credential-free tests.
It does not approve private drift bytes or a tool digest not yet presented,
issue a backfill token, delete public history, change repository rulesets,
start a VM, or authorize a model call. Those remain explicit separate actions.
The q12 authorization remains spent.

## What the historical evidence establishes

The [implementation record](M8-implementation-record.md#capture-refusal-diagnostics-after-retained-outcome-diagnosis-refs-186)
records one application attempt, g10, with a normal non-acceptance and a
grouped `capture-mismatch` fault. Adapter and callback success do not prove
application acceptance. A credential-free no-op reproduction reaches the
same refusal, proving a possible path, not what the historical executor did.
The old grouped diagnostic cannot identify which of its five comparisons
failed. Later, distinct diagnostics are prospective evidence only.

g11 and q12 did not reach the application. Their output-contract refusals
are evidence about procedure readiness, not the model's ability to perform
the task. No historical outcome is reclassified by the preparation work.

## Rehearsal evidence required before a new go request

At source baseline `f486bbe`, q12 has 19 packaged steps. Its rehearsal executes
only the combined C5/H7-H8 step and the C2 physical preflight through T5.
The former uses the real lane CLI with a scripted peer; the latter runs real
platform tools only in the provisioned Linux lane. The other named steps
have fragment or record-shape tests, not a complete accepting-path rehearsal.
Generating stdout from an expectation tests framing, not the emitter.

| Boundary | Existing proof | Missing composition evidence |
| --- | --- | --- |
| C1 controller and history | Reviewed fences and record checks | Installed-tool output and retained-history accepting path through transport |
| C2 preservation, D2 and controller/launch checks | Fragment and record-grammar tests | Real utility diagnostics and each composed step's complete output contract |
| C2 physical preflight | Real-tool Linux rehearsal | Exact successor composition and final-head Linux execution |
| C3 retained evidence and qualification | Lane/evidence-checker blocks | Isolated store accepting path without mutating a shared test fixture |
| C4 publication | Generation-floor and publication fence tests | Composed publication/activation with prior checked qualification |
| C5/H7 and conditional H8 | Real CLI, both branches and refusals | Guarded host output in the successor; synthetic drift is not measurement |
| C7 source preparation and C8 preflight | Source fences and record checks | Composed accepting paths with a genuine source bundle and isolated store |

Source references for this inventory are the q12 composition and evidence
sections, `tests/test_m8_maintenance_q12_rehearsal.py`,
`tests/test_m8_maintenance_q12_continuation.py`, and the lane/operator and
g11 suites they name. It is a baseline audit, not a claim that new tests ran.

The successor must account for every executable pre-application step. Tests
substitute only unavailable host primitives where feasible, name those
substitutions, and test both permitted output and plausible unexpected output.
Each empty-stderr rule needs an accepting-path assertion. A measured fixture
requires a stable private evidence reference; a synthetic fixture must say so.
No expectation may be inferred from the same execution it validates.

Host-only unknowns remain no-go facts to settle, not a blanket exemption for
unrehearsed steps. A disposable VM rehearsal is a possible separately scoped
proposal, not authorized by this document. Exact final-head review, CI and
measurement limits must accompany any eventual execution request.

## Independent public-text work

The scanner improvements run independently of q13: an explicitly requested
unfiltered reachable-history pass, recorded unavailable-history gaps, and
reporting of existing tags. A finished traversal is not necessarily complete
coverage. Gaps, findings, failed requests or cancellation must not produce a
clean coverage signal or automatically advance the cursor.

The live backfill and the proposed tag ruleset remain separate from the code
change. The private historical exposure must be handled without repeating
its contents in a comment, commit, test or report. This record establishes
neither removal of that exposure nor completion of a backfill.
