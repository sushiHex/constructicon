## Current decision: no useful current-main attempt is ready

The [compatibility audit](maintenance-live-compatibility.md) establishes that
installed-source C490 already supports the fixed maintenance application. A
newer main alone creates no source requirement to reinstall it. There is also
no mandatory additional N5 WRITE model fixture: fresh N4 startup and controls,
actual WRITE assembly/preflight and separately approved maintenance authority
are the existing route. N4 startup itself uses READ posture; inventing a WRITE
startup mode would add a nonexistent operation.

The task's sole output, `tests/vectors/plan_manifest.json`, is already present
on C490 and current main with the same 64 cases. Preparation requires that file
to be absent; accepted capture proves a one-file addition against the exact
base. Therefore this fixed application cannot produce a new contribution
directly against current main. Removing the file to create a synthetic base
would demonstrate the application, not improve current main. This corrects the
initial expectation behind the proposed live contribution wave.

**Recommended disposition:** deliver the repeatable credential-free workflow
and report now. Do not spend a live attempt merely to recreate an existing
artifact. Select and review a genuinely useful successor task before preparing
an executable live package. The blocker is the task/output contract, not a
missing generic launcher or an unobserved vendor refusal.

## Evidence, stop and cleanup boundary

A future selected procedure must preserve completed output, refusal and unknown
dispatch as different facts. Missing results do not prove no dispatch or permit
a new identity/retry. Use the existing attempt record and journal; retained
writer recovery must not cause another model write. Do not invent a recovery
permission beyond the selected stop/resume rule.

After a permitted attempt, require joined shutdown, affirmative lease/effect
facts and the exact candidate/gate/result relationships before reporting
acceptance. A recorded closed lease and an observed target still at base are
different from physical quiescence. The selected procedure must also prove its
required authorization withdrawal, generation/store withdrawal, park/Off and
custody release, preserving uncertainty when any proof is missing. Application
acceptance grants no installation, promotion or merge.

C490 produces schema 10. Main's diagnostic supports schema 11; the #391 report
refuses a schema-10 store explicitly as `unsupported-schema`. It must not migrate an original
private journal merely to obtain a packet. A matching historical reader or a
separately proven version-aware read-only route would be required for C490
evidence. Schema-11 metering has not thereby been deployed on the host.

No host, credential, vendor binary, model call, installation, re-baseline,
production effect or retry was performed for this preparation. Execution stays
blocked on the selected useful task and its concrete reviewed scope.
