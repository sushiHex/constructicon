# Connector liveness — shadow measurement record

Supporting evidence for
[M7.1 connector liveness rev 1](../docs/plans/milestones/M7.1-connector-liveness-rev1.md).
Written so the numbers that document cites are reproducible rather than
asserted; a review that cannot re-run them should not have to take them on
trust.

**Base:** `main` at `83ee65d`. **Method:** patch the validator to *record*
rather than refuse, run the suite, revert.

## What was measured

Two candidate admission laws, neither adopted.

1. **General connector liveness** — a connection's source must contribute a
   resolved binding at its destination. Two variants: *strict* (the source's
   own outputs) and *reach* (the source's or any of its transitive upstream's).
2. **Gather-scoped liveness** — the same, enforced only where the destination
   declares a `many` input port.

## Instrumentation

The compiler answers "was this connection load-bearing?" only if two facts are
captured at the moment they are known:

- **Provenance.** Which node produced a pool source. Captured in
  `_compile_graph` where each node's outputs are filed under `node_outputs`,
  because a source's *address* is not its producer: a composite whose output
  passes an input through returns the outer producer's address, so an
  address-keyed rule reports live edges as dead.
- **Consumption.** Which pool sources were bound at a node's declared
  boundary. Captured in `_bind_node_inputs` and in `_compile_loop`'s
  body-input loop, keyed by `(level scope, node id)`.

Both are recorded on `_Compilation`, so they live exactly as long as one
admission.

### Two defects found in the first pass, both under-reporting

Recorded because a zero that is right by accident is not evidence, and a later
reader cannot tell the two apart.

1. **`id()` reuse.** Liveness was a module-global set of `id()` values that
   outlived the objects it identified. A collected `_Source` can pass its id to
   a later one, so a source could read as live because an unrelated, long-dead
   object had been.
2. **Graph outputs leaked into liveness.** `_bind_port` also binds a graph's
   declared *outputs*. Those bindings entered the same global set, so a source
   exported by the graph read as live at any node whose pool contained it —
   exactly the panel shape the law existed for.

The corrected pass records consumption per destination and holds references for
the whole admission. The first pass's numbers are withdrawn.

## Results

### General law: four refusals

Distinct edges in graphs that admit at `83ee65d`:

| Graph | Edge | Strict | Reach |
| --- | --- | --- | --- |
| `issue-to-summary` | `announce → summarize` | dead | live |
| `architect-selection` | `right → select` | dead | dead |
| `mapped-loop` | `right → repeat` | dead | dead |
| `sdk/wider` | `helper → panel_yes` | dead | dead |

`issue-to-summary` accounted for 219 of the 234 raw findings in compilations
with no prior fault — it is the M1 vertical slice and nearly every integration
test compiles it.

### Gather-scoped law: zero refusals, and why that proved nothing

Corpus and controls in **one** instrumented run, so that a non-empty result
proves the instrumentation was live while the corpus compiled:

| | Corpus | Controls |
| --- | --- | --- |
| `rule: "gather"` findings | 0 | 1 (the drifted member) |
| `rule: "endpoint"` findings | 0 | 2 (both ghost edges) |
| Nodes whose declared boundary went unmeasured | 0 | 0 |

1359 tests, all passing: 1356 corpus plus the 3 controls. The two detectors are
reported separately because they answer different questions and a combined
"3 findings" reads as one result.

The last row is a check on the locality claim, not on the law: a finding was
recorded whenever a node with an incoming connection compiled without its
declared boundary being observed. It never fired, so consumption beneath a node
is in fact mediated entirely by that node's declared inputs.

**The zero is a fact about the corpus.** Cross-review supplied a counterexample
the corpus does not contain — `C --T--> B --U--> G` with `G` declaring `many T`,
where `G` gathers `C.T` transitively and `B` contributes nothing. Every gather
the suite exercises is atomic sources feeding one atomic gather; the only
explicit loop-boundary map test maps a scalar `one` input; composite
`many`/`optional` members are refused by SDK authoring before admission.

The corpus was never able to falsify this law. That is the finding.

## Where gathered sources actually come from

The two measurements above ask whether a *rule* fires. This one asks what the
system does, and it is the one that decided the design. Every source bound to a
`many` input port, classified by how it reached the pool:

| Graph | node.port | direct | transitive | input |
| --- | --- | --- | --- | --- |
| `test/fake-panel` | `panel_quorum.votes` | 6 | 0 | 0 |
| `test/review-panel` | `panel_quorum.votes` | 2 | 0 | 0 |
| `sdk/review-panel` | `panel_tally.votes` | 2 | 0 | 0 |
| `sdk/twice` | `tally.votes` | 2 | 0 | 0 |
| `diamond` | `collect.briefs` | 2 | 0 | 0 |
| `gathering` | `collect.briefs` | 2 | 0 | 0 |
| `sdk/wider` | `panel_tally.votes` | 2 | 0 | 0 |
| `sdk/wider` | `panel_tally.votes` | 2 | **1** | 0 |
| `sdk/wider` | `panel_tally.votes` | 2 | 0 | **1** |
| `many-input` | `repeat.state` *(already faulting)* | 0 | 0 | 1 |

*direct* — the producer has a `Connection` straight into the gathering node.
*transitive* — reachable only through the upstream closure. *input* — a graph
input, which sits in every node's pool.

**Every gather in this repository is exactly its directly-connected sources**,
except `sdk/wider`, which was written to demonstrate that it need not be, and
one negative test. So scoping a `many` port to its connections is a law the
corpus already satisfies — and it dissolves the counterexample above, because
`C.T` is then not in `G`'s pool for `B → G` to be credited with.

The first two measurements looked for a rule that fired on nothing. This one
found the rule by looking at what the system already does.

## Controls

An unfired detector proves nothing.

**Positive, gather.** `sdk/panel-yes` registered and promoted with an output of
`sdk/Verdict` where the authored panel expects `sdk/Vote`. Admission succeeds
and the gather holds one member where two were connected. One finding, on
`panel_yes → panel_tally`, and nothing else.

**Negative.** The same panel undrifted, in the same run. Silent, as required —
otherwise "no corpus findings" would only mean the detector was broken in a way
the corpus happened not to reveal.

**Positive, endpoint.** Two connections appended to a valid panel graph,
`ghost → panel_tally` and `panel_yes → phantom`, neither endpoint a node. Both
admit; `resolved_connections` is identical to the clean graph's and
`manifest_hash` is not.

## Known limits

- **A Loop's synthetic body node is not observed.** `_compile_loop` gathers
  body inputs into `GraphInputAddress` values and then compiles a synthetic
  `$body` node from them *outside* `_compile_graph`'s traversal. The
  provenance recorder reads the boundary ledger only for nodes that traversal
  visits, so a `many` input on a Loop body is bound twice and classified never.
  The "every gather" claim above is therefore every gather `_compile_graph`
  traverses. Found by cross-review after the numbers were first cited.
- **Provenance is incomplete for explicit selectors.** `_resolve_selector`
  reads `node_lookup`, not the pool, so it can return a source that never
  entered the pool; the instrumentation attributes that source to no origin.
- **Admission success is sampled, not concluded.** The recorder samples
  `comp.faults` while compiling one node; later nodes, graph-output binding, or
  the final fault check can still reject the graph.
- **Findings are keyed by graph name and scope, not by a graph digest**, so
  same-named variants across tests are conflated.

None of these affect the negative conclusion, which rests on counterexamples
rather than on counts.

## Reproducing

The patches themselves are retained in `m7.1-measurement/`, rather than
described — a prose description of this instrumentation was tried first and was
not reproducible, because it omitted the dataclass field defaults, the
recorder, and the controls.

| File | What it is |
| --- | --- |
| `shadow_general_law.py` | Patches the validator to record the general law, strict and reach — produced `raw-general-law.jsonl` |
| `shadow_liveness.py` | Patches it to record gather-scoped liveness and ghost endpoints — produced `raw-gather-law.jsonl` |
| `shadow_gather_provenance.py` | Patches it to classify every `many`-port source as direct / transitive / input — produced `raw-gather-provenance.jsonl` |
| `controls.py` | The three control graphs; copy to `tests/sdk/test_m71_controls.py` to run |
| `raw-general-law.jsonl` | 234 findings from the general law |
| `raw-gather-law.jsonl` | 3 findings from the gather law — all from the controls |
| `raw-gather-provenance.jsonl` | 16 rows: every gather `_compile_graph` traverses, by source origin |

Each patch asserts on every anchor it replaces, so it fails loudly against a
validator that has moved — or one already patched — rather than silently
mis-patching. Apply each to a clean checkout; they are not idempotent.

```bash
cp research/m7.1-measurement/controls.py tests/sdk/test_m71_controls.py
uv run python research/m7.1-measurement/shadow_gather_provenance.py
CONSTRUCTICON_GATHER_OUT=/tmp/gather.jsonl uv run python -m pytest -q -p no:randomly
git checkout src/constructicon/runtime/validator.py
rm tests/sdk/test_m71_controls.py
```

`shadow_liveness.py` reads `CONSTRUCTICON_LIVENESS_OUT` instead. Both append,
so clear the file between runs.

### Reading the counts

`raw-gather-law.jsonl` holds three findings, and they come from **two
different detectors** in one run — one `rule: "gather"` from the drifted-member
control, and two `rule: "endpoint"` from the ghost-connection control. The
corpus contributed none to either.
